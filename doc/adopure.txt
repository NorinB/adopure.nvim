                                                                       *adopure*

                                                                   *adopure.cli*
The plugin provides an opinionated workflow to interact with Azure DevOps Pull Requests.

adopure.lua contains the main nvim command line entry point of the plugin.
The entry-point is called using the command: AdoPure.
The command is auto-completing when used in neovim command line. Valid options include:

>vim
 :AdoPure [ load ] [ context | threads ] [ opts ]
<
Loads specified argument into state.

     *context*: load open pull requests; prompt user to pick one.
     The open pull requests are fetched again on every call.
     With the pull_request_from_branch config, the pull request of the checked out branch
     is taken without prompting; pass {pick=true} to prompt anyway.
     If that pull request is loaded already, it is kept and only the review is opened.
     Note: Subsequent commands will operate on the chosen PR.

     *threads*: Fetch comment threads from Azure DevOps.

>vim
 :AdoPure [ open ] [ pull_request | quickfix | thread_picker | new_thread | existing_thread ] [ opts ]
<
Opens specified argument in the editor.

     *pull_request*: Open a read-only overview buffer of the whole pull request.
     Shows details, reviewer votes, description and a timeline of all comment threads.
     Supports the same thread_filters as the thread_picker.
     If no pull request is loaded yet, one is chosen first as for load context;
     this loads it without checking it out or opening the diff viewer.

     *quickfix*: Open comment threads in quickfix window.

     *thread_picker*: Open a picker with all comment threads.
     Supports filtering like so:
>vim
     :AdoPure open thread_picker {thread_filters={'hide_system', 'hide_closed'}}
<
     *new_thread*: Opens a window to write a comment on code selection.

     *existing_thread*: Opens a window with an existing comment thread.

>vim
 :AdoPure [ submit ] [ comment | vote | thread_status | delete_comment | edit_comment ] [ opts ]
<
Submits specified argument to Azure DevOps.

     *comment*: Submit new comment or reply; must be in new_thread or existing_thread window.

     *vote*: Submit a new vote on the pull request.

     *thread_status*: Submit a thread_status change; must be in existing_thread window.

     *delete_comment*: Delete one of your own comments; must be in existing_thread window.

     *edit_comment*: Edit one of your own comments; must be in existing_thread window.

>vim
 :AdoPure [ unload ]
<
Unloads plugin state and remove plugin marks.

Note: If no arguments args provided, the user will be prompted.

                                                           *adopure.config.meta*

The plugin is configured by assigning an adopure.Config table to vim.g.adopure.
>lua
 vim.g.adopure = {}
<
There is no mechanism built-in to securely load secrets.
If you have a cli command that will produce the secret, consider doing something like this:
>lua
 local nio = require("nio")
 nio.run(function()
     local secret_job = nio.process.run({ cmd = "pass", args = { "show", "my_pat_token_secret_name"} })
     vim.g.adopure = { pat_token = secret_job.stdout.read():sub(1, -2) }
 end)
<
Alternatively, you can set it as environment variable.

==============================================================================
                                                              *adopure.checkout*

Checking out a pull request is configured with checkout_methods and on_checkout.
It happens when a pull request context is loaded and its source is not checked out yet.

With one configured method, that method is used right away.
With several, a prompt lets you choose one; cancelling it continues without a checkout.
With an empty list, nothing is ever checked out.
When checkout_methods is not set, a prompt asks whether to check out the source commit detached.
A configured list replaces that default completely; include "detached" to keep it as a choice.

A method is one of:
     A builtin name: "detached" checks out the source commit, "switch" runs git switch on the source branch.
     A table with a name and a command.
     A function returning such a table, or a name and a command.
     It is called when the methods are listed, so before one is chosen.

A command is one of:
     A string, run through the shell. Placeholders are shell escaped, so do not quote them.
     A list of arguments, run without a shell.
     A function returning a string, a list, or nil when it did the checkout itself.
     It is called only once its method is chosen.

Placeholders are {branch}, {target}, {commit}, {id} and {remote}.
Functions receive the same values as an adopure.CheckoutContext.

A failing checkout is reported and stops the pull request from being opened in the diff viewer.
on_checkout runs after every successful checkout, for example to change into a new worktree.
The repository root is read again afterwards.
>lua
 vim.g.adopure = {
     checkout_methods = {
         "switch",
         { name = "worktree", command = "git worktree add ../{branch} {branch}" },
     },
     on_checkout = function(context)
         if context.method == "worktree" then
             vim.cmd.cd("../" .. context.branch)
         end
     end,
 }
<

M.open({state}, {opts})                                                 *M.open*
    Open the active pull request in a read-only overview buffer.
    Shows title, branches, status, reviewer votes, description and a timeline of all comment threads.
    The buffer follows the loaded state; it re-renders whenever it is entered.
    It has filetype adopure with the markdown parser; add that filetype to markdown plugins to style it.
    Buffer keymaps:
         <CR>: Jump to the code of the comment thread under the cursor and open its thread window.
         R: Fetch pull request and comment threads from Azure DevOps again.
         ]] and [[: Jump to the next or previous comment thread.

    Parameters: ~
        {state}  (adopure.AdoState)
        {opts}   (adopure.OpenPullRequestOpts)

    Returns: ~
        (number)  bufnr
